# P3-2 — `restoreEnv()` only restores `LANG` and `LC_ALL`; gettext also reads …

## Finding / 问题

- EN: `restoreEnv()` only restores `LANG` and `LC_ALL`; gettext also reads `LANGUAGE`, so a failed construction can still leave a trace in environments that set it.
- 中文: restoreEnv() 只还原 LANG 与 LC_ALL；gettext 还会读 LANGUAGE，因此在设置了它的环境里构造失败仍可能留痕。
- Where / 位置: `src/GettextTranslator.php:44-47,77-86`
- Verification / 验证: static / 仅静态推断

- 2026-09-29 · `owner — migears-i18n` · `rejected` — the described trace cannot exist: the constructor
  never writes `LANGUAGE`, so there is nothing of it to restore. `grep -n LANGUAGE src/` returns nothing;
  the only environment variables the constructor mutates are `LANG` and `LC_ALL` 
  (`src/GettextTranslator.php:51-52`), and those are exactly the two it captures 
  (`src/GettextTranslator.php:49`) and restores (`src/GettextTranslator.php:79-88`). `restoreEnv()` therefore
  already restores the full set the construction can have disturbed — the premise of the finding, that a
  failed construction can leave a trace in `LANGUAGE`, does not hold.

  Reproduction (temp dir outside every repo, the module's own `vendor/autoload.php`; PHP 8.5.10, gettext
  present), two scenarios — `LANGUAGE=de_DE.UTF-8` with `LANG`/`LC_ALL` previously **unset**, and with them
  previously **set**: after a failed construction (`setlocale('xx_XX.UTF-8')` returns false, `RuntimeException`
  thrown) `LANGUAGE`, `LANG`, `LC_ALL` and the C locale are each byte-identical to their pre-construction
  values. No trace in either scenario.

  The design is deliberate and already documented in both README halves (`README.md:116-120`,
  `README.md:413-416`): "This class does not touch `LANGUAGE`; unset it if `locale:` is meant to be
  authoritative." Restoring a variable the class never sets would be a no-op, so there is nothing here to fix.

  Note the opposite request, should it be what is actually meant — the class *setting/unsetting* `LANGUAGE`
  so `locale:` outranks a pre-set `LANGUAGE` — is a behaviour change, not a restore-set fix, and a decision
  the user owns; I have not folded it into this item. Ask and I will raise it as its own question.

  owner — migears-i18n
